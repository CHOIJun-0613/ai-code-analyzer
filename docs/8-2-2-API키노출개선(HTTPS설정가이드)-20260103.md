## 1. 개요

### 1.1 왜 HTTPS가 필요한가?

**현재 문제점 (HTTP):**
- ❌ API 키가 평문으로 네트워크 전송
- ❌ 중간자 공격(MITM) 가능성
- ❌ 세션 하이재킹 위험
- ❌ 데이터 위변조 가능

**HTTPS 적용 후:**
- ✅ 모든 데이터 암호화 전송 (TLS 1.3)
- ✅ 서버 신원 검증 (인증서)
- ✅ 데이터 무결성 보장
- ✅ 최신 브라우저 보안 기능 활용

### 1.2 현재 구조

```
Client (React + Vite)          Server (FastAPI + Uvicorn)
http://localhost:5173    -->   http://localhost:8000
         ↓                              ↓
    (변경 필요)                    (변경 필요)
         ↓                              ↓
https://localhost:5173   -->   https://localhost:8443
```

## 2. 개발 환경 HTTPS 설정

### 2.1 자체 서명 인증서 생성

#### 방법 A: mkcert 사용 (권장)

**1단계: mkcert 설치**

**Windows (Chocolatey):**
```powershell
# Chocolatey 설치 (관리자 권한 PowerShell)
Set-ExecutionPolicy Bypass -Scope Process -Force
[System.Net.ServicePointManager]::SecurityProtocol = [System.Net.ServicePointManager]::SecurityProtocol -bor 3072
iex ((New-Object System.Net.WebClient).DownloadString('https://community.chocolatey.org/install.ps1'))

# mkcert 설치
choco install mkcert
```

**Windows (수동 설치):**
1. https://github.com/FiloSottile/mkcert/releases 접속
2. `mkcert-v1.4.4-windows-amd64.exe` 다운로드
3. `mkcert.exe`로 이름 변경
4. `C:\Windows\System32\` 또는 PATH에 추가

**macOS:**
```bash
brew install mkcert
brew install nss # Firefox용
```

**Linux:**
```bash
# Ubuntu/Debian
sudo apt install libnss3-tools
wget -O mkcert https://github.com/FiloSottile/mkcert/releases/download/v1.4.4/mkcert-v1.4.4-linux-amd64
chmod +x mkcert
sudo mv mkcert /usr/local/bin/
```

**2단계: 로컬 CA 설치 및 인증서 생성**

```bash
# 프로젝트 루트로 이동

# - localhost+2.pem (인증서)
# - localhost+2-key.pem (개인키)
```

```bash

# 자체 서명 인증서 생성 (유효기간 365일)
```

#### 방법 B: Python 스크립트로 실행

**파일: `server/run_https.py` (새로 생성)**

```python
"""
개발 환경용 HTTPS 서버 실행 스크립트
"""
import uvicorn
import os
from pathlib import Path

def main():
    # 환경 감지
    environment = os.getenv("ENVIRONMENT", "development")

    # 인증서 경로
    cert_dir = Path(__file__).parent.parent / "certs"
    ssl_keyfile = str(cert_dir / "localhost+2-key.pem")
    ssl_certfile = str(cert_dir / "localhost+2.pem")

    if environment == "development":
        print("🔐 Starting HTTPS Development Server...")
        print(f"📂 Cert Directory: {cert_dir}")
        print(f"🔑 SSL Key: {ssl_keyfile}")
        print(f"📜 SSL Cert: {ssl_certfile}")

        # 인증서 파일 존재 확인
        if not os.path.exists(ssl_keyfile) or not os.path.exists(ssl_certfile):
            print("\n❌ ERROR: SSL certificate files not found!")
            print("Please run the following commands:")
            print("  cd certs")
            print("  mkcert localhost 127.0.0.1 ::1")
            return

        # HTTPS 개발 서버 실행
        uvicorn.run(
            "app.main:app",
            host="localhost",
            port=8443,
            reload=True,
            ssl_keyfile=ssl_keyfile,
            ssl_certfile=ssl_certfile,
            log_level="info"
        )
    else:
        # 프로덕션 환경은 Nginx가 HTTPS 처리
        print("🚀 Starting Production Server (HTTP)...")
        uvicorn.run(
            "app.main:app",
            host="0.0.0.0",
            port=8000,
            workers=4,
            log_level="info"
        )

if __name__ == "__main__":
    main()
```

## 3. 프로덕션 환경 HTTPS 설정

### 3.1 아키텍처 개요

```
Internet
   ↓
Nginx (HTTPS :443)
   ↓ HTTP
FastAPI (HTTP :8000)
```

**역할 분담:**
- **Nginx**: HTTPS 종단, SSL/TLS 처리, 정적 파일 서빙, 리버스 프록시
- **FastAPI**: HTTP로 실행, 비즈니스 로직 처리

### 3.2 Let's Encrypt 인증서 발급

#### 사전 요구사항
- 도메인 등록 및 DNS 설정 완료
- 포트 80, 443 외부 접근 가능
- Ubuntu/Debian 서버

#### 1단계: Certbot 설치

```bash
# 시스템 업데이트
sudo apt-get update
sudo apt-get upgrade -y

# Certbot 및 Nginx 플러그인 설치
sudo apt-get install certbot python3-certbot-nginx -y
```

#### 2단계: 인증서 발급

```bash
# 자동 발급 및 Nginx 설정
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com

# 대화형 프롬프트:
# - 이메일 입력 (갱신 알림용)
# - 약관 동의
# - HTTP -> HTTPS 리다이렉트 설정: Yes (2번 선택)
```

#### 3단계: 인증서 확인

```bash
# 인증서 위치
ls -la /etc/letsencrypt/live/yourdomain.com/

# 파일 목록:
# - fullchain.pem (인증서 체인)
# - privkey.pem (개인키)
# - cert.pem (서버 인증서)
# - chain.pem (중간 인증서)
```

### 3.3 Nginx 설정

#### 파일: `/etc/nginx/sites-available/ai-code-analyzer`

```nginx
# HTTP -> HTTPS 리다이렉트
server {
    listen 80;
    listen [::]:80;
    server_name yourdomain.com www.yourdomain.com;

    # Let's Encrypt ACME Challenge (인증서 갱신용)
    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    # 모든 HTTP 트래픽을 HTTPS로 리다이렉트
    location / {
        return 301 https://$host$request_uri;
    }
}

# HTTPS 메인 서버
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name yourdomain.com www.yourdomain.com;

    # ========== SSL 인증서 ==========
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    # ========== SSL 보안 설정 ==========
    # TLS 프로토콜 버전 (TLS 1.2, 1.3만 허용)
    ssl_protocols TLSv1.2 TLSv1.3;

    # 암호화 스위트 (최신 보안 권장 설정)
    ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384';
    ssl_prefer_server_ciphers off;

    # SSL 세션 캐시
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;
    ssl_session_tickets off;

    # OCSP Stapling (인증서 검증 성능 향상)
    ssl_stapling on;
    ssl_stapling_verify on;
    ssl_trusted_certificate /etc/letsencrypt/live/yourdomain.com/chain.pem;
    resolver 8.8.8.8 8.8.4.4 valid=300s;
    resolver_timeout 5s;

    # ========== 보안 헤더 ==========
    # HSTS (HTTP Strict Transport Security)
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

    # XSS 방어
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-XSS-Protection "1; mode=block" always;

    # Referrer 정책
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Permissions Policy
    add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;

    # ========== 로그 파일 ==========
    access_log /var/log/nginx/ai-analyzer-access.log;
    error_log /var/log/nginx/ai-analyzer-error.log;

    # ========== 정적 파일 (React 빌드) ==========
    location / {
        root /var/www/ai-code-analyzer/client/dist;
        try_files $uri $uri/ /index.html;

        # 정적 리소스 캐싱
        location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
            expires 1y;
            add_header Cache-Control "public, immutable";
            access_log off;
        }

        # HTML 파일 캐싱 비활성화
        location ~* \.html$ {
            expires -1;
            add_header Cache-Control "no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0";
        }
    }

    # ========== API 프록시 (FastAPI) ==========
    location /api {
        # FastAPI 서버로 프록시
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;

        # WebSocket 지원
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 헤더 전달
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port $server_port;

        # 타임아웃 설정 (분석 작업이 오래 걸릴 수 있음)
        proxy_connect_timeout 300s;
        proxy_send_timeout 300s;
        proxy_read_timeout 300s;

        # 버퍼 설정
        proxy_buffering off;
        proxy_request_buffering off;
    }

    # ========== 파일 업로드 크기 제한 ==========
    client_max_body_size 100M;

    # ========== Gzip 압축 ==========
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml text/javascript application/json application/javascript application/xml+rss application/rss+xml font/truetype font/opentype application/vnd.ms-fontobject image/svg+xml;
}
```

```python
    NEO4J_USER: str
    NEO4J_PASSWORD: str
    NEO4J_DATABASE: Optional[str] = "neo4j"

    # ... (기타 설정)

    class Config:
        # 환경에 따라 다른 .env 파일 로드

        case_sensitive = True

settings = Settings()
```

## 5. 문제 해결

### 5.1 인증서 관련 오류

#### 문제: "NET::ERR_CERT_AUTHORITY_INVALID"

**원인:** 자체 서명 인증서를 브라우저가 신뢰하지 않음

**해결:**
```bash
# mkcert CA 재설치
mkcert -install

# 브라우저 재시작
```

#### 문제: "unable to get local issuer certificate"

**원인:** Node.js가 자체 서명 인증서를 거부

**해결 (임시, 개발용):**
```bash
# Windows
set NODE_TLS_REJECT_UNAUTHORIZED=0
npm run dev

# Linux/macOS
NODE_TLS_REJECT_UNAUTHORIZED=0 npm run dev
```

**권장 해결:**
```typescript
// vite.config.ts에서 secure: false 설정
proxy: {
    '/api': {
        target: 'https://localhost:8443',
        changeOrigin: true,
        secure: false,  // 자체 서명 인증서 허용
    }
}
```

### 5.2 Mixed Content 경고

#### 문제: HTTPS 페이지에서 HTTP 리소스 로드 차단

**확인:**
```
Mixed Content: The page at 'https://localhost:5173/' was loaded over HTTPS,
but requested an insecure resource 'http://example.com/image.jpg'.
This request has been blocked.
```

**해결:**
1. 모든 외부 리소스 URL을 HTTPS로 변경
2. 상대 경로 사용
3. 프로토콜 상대 URL 사용: `//example.com/image.jpg`

### 5.3 Nginx 설정 오류

#### 문제: "nginx: [emerg] cannot load certificate"

**원인:** 인증서 파일 경로 또는 권한 문제

**해결:**
```bash
# 인증서 파일 존재 확인
ls -la /etc/letsencrypt/live/yourdomain.com/

# 파일 권한 확인
sudo chmod 644 /etc/letsencrypt/live/yourdomain.com/fullchain.pem
sudo chmod 600 /etc/letsencrypt/live/yourdomain.com/privkey.pem

# Nginx 사용자가 읽을 수 있는지 확인
sudo -u www-data cat /etc/letsencrypt/live/yourdomain.com/fullchain.pem
```

#### 문제: "502 Bad Gateway"

**원인:** FastAPI 서버가 실행되지 않거나 연결 불가

**해결:**
```bash
# FastAPI 서버 상태 확인
sudo systemctl status ai-analyzer

# 로그 확인
sudo journalctl -u ai-analyzer -n 50

# 포트 확인
netstat -tuln | grep 8000

# 방화벽 확인
sudo ufw status
```

### 5.4 Let's Encrypt 갱신 실패

#### 문제: "Certbot failed to authenticate some domains"

**원인:** 80번 포트 접근 불가 또는 DNS 설정 오류

**해결:**
```bash
# 포트 80이 열려있는지 확인
sudo netstat -tuln | grep :80

# Nginx가 80번 포트를 사용 중인지 확인
sudo systemctl status nginx

# DNS 전파 확인
nslookup yourdomain.com
dig yourdomain.com

# 수동 갱신 시도 (디버그 모드)
sudo certbot renew --dry-run --verbose
```

# 코드 분석 중단 시 데이터 처리 방법

코드 분석 중단 시 분석 결과 데이터(Neo4j)가 처리되는 방식에 대한 설명입니다.

백엔드 분석 프로세스는 작업 수행 중 주기적으로 중단 신호(로그 폴더 내 특정 파일)를 확인하며, 신호가 감지되면 즉시 작업을 멈춥니다. 이때 데이터베이스에 저장되는 결과는 **분석 시작 시 선택한 저장 옵션**에 따라 다음과 같이 달라집니다.

### 1. 삭제 후 저장 (Delete and Save)
기존 프로젝트 데이터를 완전히 삭제하고 새로운 분석 결과로 대체하는 방식입니다.

*   **동작 과정:**
    1.  분석 시작과 동시에 해당 프로젝트의 **모든 기존 데이터(노드 및 관계)를 Neo4j에서 영구 삭제**합니다.
    2.  이후 코드를 분석하며 새로운 데이터를 순차적으로 저장합니다.
*   **중단 시 결과:**
    *   이미 기존 데이터가 삭제되었으므로, **이전 분석 결과는 복구할 수 없습니다.**
    *   데이터베이스에는 중단된 시점까지 처리되어 저장된 **일부 데이터**만 남게 됩니다.
    *   **결론:** 프로젝트 데이터가 **불완전한 상태**(또는 중단 시점에 따라 비어 있는 상태)가 됩니다.

### 2. 업데이트 저장 (Update Save)
기존 데이터를 유지하면서 변경된 사항을 추가하거나 갱신하는 방식입니다.

*   **동작 과정:**
    1.  기존 데이터를 삭제하지 않고 그대로 둡니다.
    2.  분석된 내용을 바탕으로 Neo4j에 새로운 노드를 생성하거나 기존 노드를 갱신(`MERGE` 작업)합니다.
*   **중단 시 결과:**
    *   분석이 현재 실행 중인 단계에서 멈춥니다.
    *   이미 처리되어 DB에 반영된 데이터는 저장된 상태로 유지됩니다.
    *   아직 처리되지 않은 나머지 데이터는 반영되지 않습니다.
    *   **결론:** 기존 데이터와 일부 갱신된 데이터가 섞인 **혼합된 상태**가 되며, 데이터 간의 **정합성(Consistency)이 깨질 수 있습니다** (예: 클래스 정보는 갱신되었으나, 그에 따른 관계 정보는 아직 갱신되지 않은 경우).

### 요약 및 권장 사항
두 경우 모두 시스템 차원에서 **자동 롤백(Rollback) 기능은 제공되지 않습니다.** 즉, 분석 시작 전의 상태로 되돌아가지 않습니다.

*   **삭제 후 저장:** 데이터 유실 위험 (구 데이터 삭제됨, 신규 데이터 불완전)
*   **업데이트 저장:** 데이터 불일치 위험 (구 데이터 + 일부 신규 데이터 혼재)

따라서 분석을 중단한 경우, 데이터의 완전성을 보장하기 위해 **가급적 "삭제 후 저장" 옵션으로 분석을 처음부터 다시 실행**하는 것을 권장합니다.

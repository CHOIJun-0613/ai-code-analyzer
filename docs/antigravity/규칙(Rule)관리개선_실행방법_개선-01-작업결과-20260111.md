# 규칙(Rule)관리 개선 및 실행 방법 개선 작업 결과

## 1. 개요

본 문서는 규칙(Rule) 기반의 코드 분석 시스템을 개선하기 위한 작업 결과를 기술한다.
서버 사이드에서는 규칙을 DB(Neo4j)에 저장하고 동적으로 로드하도록 변경하였으며, 클라이언트 사이드에서는 이러한 규칙을 관리(등록, 수정, 삭제, 순서 변경)할 수 있는 UI를 구현하였다.

## 2. 작업 내용

### 2.1 Server Side

- **DB Schema (Neo4j)**
  - 노드: `AnalysisRule`
  - 속성: `id`, `name`, `description`, `content`, `useYn`, `order`, `updatedAt`, `updatedBy`, `isSystem`
- **API Implementation (`/api/v1/analysis-rules`)**
  - `GET /`: 규칙 목록 조회 (active_only 옵션 지원)
  - `POST /`: 규칙 생성
  - `PUT /{id}`: 규칙 수정
  - `DELETE /{id}`: 규칙 삭제
  - `PUT /reorder`: 규칙 순서 일괄 변경
- **Logic Change**
  - `AnalysisRuleService`: 규칙 CRUD 및 캐싱(필요 시) 로직 담당.
  - `RulesManager`: 기존 파일 로딩 방식을 `AnalysisRuleService`를 통한 DB 로딩 방식으로 변경.
  - `import_rules.py`: 기존 파일 기반 규칙을 DB로 마이그레이션하는 스크립트 작성 및 실행 완료.

### 2.2 Client Side

- **Rule Management UI (`/rules`)**
  - **List View**: 규칙 목록 표시, 사용 여부 토글, 삭제 버튼.
  - **Reorder**: Drag & Drop (`@dnd-kit`)을 이용한 직관적인 순서 변경 기능.
  - **Editor**: Markdown Editor (`@uiw/react-markdown-editor`)를 통한 규칙 내용 편집 및 하이라이팅 지원.
- **Integration**
  - `Sidebar`: 'Analysis Management' 섹션에 'Rules' 메뉴 추가.
  - `Layout`: 다국어(i18n) 및 다크 모드 지원 적용.

## 4. 실행 및 검증 방법

1. **서버 실행**:

   ```bash
   cd server
   runvenv.bat
   python main.py
   ```

2. **클라이언트 실행**:

   ```bash
   cd client
   npm run dev
   ```

3. **접속 및 확인**:
   - `http://localhost:5173/rules` 접속.
   - 규칙 목록이 보이는지 확인 (기존 파일들이 Migration 되었다면 보임).
   - "New Rule" 버튼으로 새 규칙 생성.
   - 드래그 앤 드롭으로 순서 변경 후 새로고침하여 유지되는지 확인.
   - "Active" 토글 동작 확인.
   - 분석 실행 시 로그에 DB에서 로드된 규칙이 적용되는지 확인.

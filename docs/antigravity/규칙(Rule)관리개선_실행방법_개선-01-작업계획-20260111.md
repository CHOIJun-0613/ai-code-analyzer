# 규칙(Rule)관리 개선 및 실행 방법 개선 작업 계획

## 1. 개요

본 문서는 규칙(Rule) 기반의 코드 분석 시스템을 개선하기 위한 작업 계획을 기술한다.
규칙을 DB에 저장하여 관리하고, 클라이언트에서 이를 편집/설정할 수 있는 UI를 제공하며, 서버에서는 설정된 규칙을 동적으로 로드하여 분석에 적용하는 것을 목표로 한다.

## 2. 작업 범위

### 2.1 Server Side

- **DB Schema (Neo4j)**
  - 노드: `AnalysisRule`
  - 속성: `id`, `name`, `description`, `content`, `useYn`, `order`, `updatedAt`, `updatedBy`
  - Label: `System` (시스템 기본 규칙인 경우)
- **API Implementation**
  - `GET /api/v1/analysis-rules`: 규칙 목록 조회
  - `POST /api/v1/analysis-rules`: 규칙 생성
  - `PUT /api/v1/analysis-rules/{id}`: 규칙 수정
  - `DELETE /api/v1/analysis-rules/{id}`: 규칙 삭제
  - `PUT /api/v1/analysis-rules/reorder`: 규칙 순서 변경
- **Logic Implementation**
  - 분석 시작 시 (`start_analysis`), 활성화된(`useYn=true`) 규칙을 `order` 순으로 로드.
  - 기존 하드코딩된 규칙 로직을 DB 기반 동적 로딩으로 대체 또는 병합.

### 2.2 Client Side

- **Rule Management UI**
  - **List View**: 규칙 목록, 사용 여부 스위치, 순서 변경 (Drag & Drop).
  - **Editor**: Markdown 편집기 지원 (규칙 내용 작성용).
  - **Form**: 규칙명, 설명 등 메타데이터 입력.
- **Integration**
  - API 연동 및 상태 관리 (React Query 등 활용).
  - i18n 및 Dark/Light 모드 적용.

## 1. 분석 실행 상태 유지

### 현황 분석
- 현재 `useQuery(['analysis', 'active'])`를 통해 활성 작업 ID와 상태는 가져오고 있으나, 기존 로그 데이터는 복구되지 않음.
- WebSocket은 연결 이후의 로그만 수신하므로, 화면 전환 후 복귀 시 로그 창이 비어 있게 됨.

### 개선 계획
- `jobId`가 존재할 때 해당 작업의 전체 로그를 가져오는 `useQuery(['analysis', 'job', jobId, 'logs'])` 추가.
- 쿼리 결과가 반환되면 `setLogs`를 통해 상태 업데이트.

## 2. "Path Mode" 레이블 개선

### 현황 분석
- "Path Mode" / "Upload Mode" 표시가 사용자에게 큰 의미가 없다는 피드백.
- 대신 "로그 레벨" 정보를 보여주어 현재 분석 설정을 직관적으로 확인하게 함.

### 개선 계획
- 해당 위치의 텍스트를 `로그 레벨: {logLevel}` 형식으로 변경.

## 3. 분석 실행 옵션 표시 순서 변경

### 현황 분석
- 현재 `Target`, `Strategy`, `Project` 순으로 표시됨.
- 사용자는 `Project`를 가장 중요하게 생각하므로 가장 왼쪽에 배치 요청.

### 개선 계획
- JSX 내의 렌더링 순서를 `Project` -> `Target` -> `Strategy` 순으로 변경.

# 클래스 개별 재분석 기능 구현 방안 (Class Individual Analysis Plan)

## 1. 개요 (Overview)

사용자가 특정 클래스의 분석 결과가 미흡하거나, AI 분석을 추가/갱신하고 싶을 때 **전체 프로젝트를 다시 분석하지 않고 해당 클래스만 빠르고 간편하게 재분석**할 수 있는 기능을 제공합니다.

## 2. 화면 설계 (UI/UX Design)

### 2.1. 진입점 (Entry Point)

- **위치:** `ClassDetails` 화면 헤더 상단.
- **배치:** 우측 상단 '산출물' (Reports) 드롭다운 버튼의 **왼쪽**에 '재분석' (Re-analyze) 버튼 추가.
- **스타일:**
  - 아이콘: `RefreshCw` (회전 화살표) 또는 `Play` (프로젝트 아이콘 스타일 통일)
  - 텍스트: "재분석" (영문: "Re-analyze")

### 2.2. 재분석 팝업 모달 (Re-analysis Modal)

**[상태 1: 설정 (Settings)]**
분석 시작 전 옵션을 설정하는 화면입니다.

1. **정적 분석 설정:**
    - *단일 파일 분석이므로 병렬 처리(Threads) 설정 등은 제외하고, 파싱 로직에 영향을 주는 핵심 옵션만 노출합니다.*
    - [체크박스] DTO 소스 제외 (Skip DTO Source)
    - [체크박스] DTO 메서드 제외 (Skip DTO Methods)
    - **조건부 활성화:** 현행 `ClassDetails` 화면의 **DTO 뱃지 표시 로직(`classData.sub_type`)과 동일한 기준**을 적용하여, **DTO가 아닌 경우** 위 두 체크박스를 **비활성화(Disabled)** 처리합니다.
2. **AI 분석 설정:**
    - [토글 스위치] **AI 분석 포함 (Include AI Analysis)**
        - 기본값: OFF (사용자가 명시적으로 켤 수 있도록 함)
3. **푸터:** [취소], [분석 시작]

![Class Re-analysis Settings Mockup](/class_reanalysis_modal_v2_mockup_1768015718781.png)

**[상태 2: 분석 진행 중 (In Progress / Log View)]**
'분석 시작' 버튼 클릭 시, 설정 영역이 **로그 뷰어**로 전환됩니다.

1. **로그 터미널:**
    - 실시간으로 수신되는 WebSocket 로그를 출력하는 검은 배경의 터미널 영역.
    - **로그 통합:** 정적 분석(Parsing)이 먼저 수행되고, 이어서 AI 분석이 수행됩니다. 두 단계의 로그는 **하나의 터미널 창에 순차적으로 통합되어 출력**되므로 사용자는 전체 흐름을 한곳에서 확인할 수 있습니다.
2. **진행률 (Progress):** 로그 하단에 진행 상태 바(Progress Bar) 표시.
3. **푸터:**
    - [중단] (Stop): 분석을 취소하고 중단합니다.
    - [닫기] (Close): 분석 완료 전까지 비활성화(Disabled), 완료 시 활성화.

## 3. 기능 요건 (Functional Requirements)

### 3.1. 범위 및 정책 (Scope & Policy)

- **분석 범위:** 단일 클래스 파일의 변경사항만 현행화 (의존성 분석 제외).
- **DTO 판단 및 UI 처리:**
  - **판단 기준:** `classData.sub_type` 값을 확인합니다. (기존 UI의 DTO 뱃지 표시 로직과 동일)
  - **Non-DTO Class:** `sub_type`이 'DTO'가 아닌 경우, 'DTO 소스 제외', 'DTO 메서드 제외' 체크박스 Disabled.
  - **DTO Class:** `sub_type`이 'DTO'인 경우, 체크박스 Enabled (기본값은 사용자 설정 따름).

### 3.2. 단일 클래스 분석 실행

- **API 호출:** `POST /projects/{projectName}/classes/{className}/analyze`
- **Payload:** `analysis_target: target_file`, `include_ai`, `skip_dto_source/methods` 등.

### 3.3. 실시간 진행 상태 및 로그 (Real-time Logs)

- WebSocket을 통해 실시간 파싱/AI 분석 로그 수신 및 표시.
- **순차 실행:** 일반적으로 '소스 파싱(정적 분석)' -> 'AI 분석(선택 시)' 순서로 진행되며, 모든 로그는 동일한 Job ID로 스트리밍되어 UI에 표시됩니다.
- 완료 후 UI 자동 갱신.

## 4. 기술 구현 방안 (Technical Implementation)

### 4.1. Frontend

- `client/src/components/ClassAnalysisModal.tsx`:
  - 내부 상태(`step`: `'settings' | 'running' | 'completed'`)를 두어 UI 렌더링 분기.
  - `running` 상태일 때 `LogViewer` 컴포넌트(기존 `Analysis.tsx` 참조) 렌더링.
  - **DTO 판단:** `props.classData.sub_type === 'DTO'` (대소문자 처리 주의) 조건을 사용.

### 4.2. Backend (Contract Assumption)

- Backend는 입력받은 파일 경로 하나에 대해서만 파싱 파이프라인을 실행합니다.
- AI 분석 요청 시, 파싱이 완료된 후 해당 결과(Method Context 등)를 토대로 LLM을 호출합니다.
- 모든 과정의 로그는 Client가 구독 중인 WebSocket 채널로 전송해야 합니다.

## 5. 검증 계획 (Verification Plan)

1. **설정 화면 확인:**
    - `ClassDetails` 화면에서 DTO 뱃지가 없는 클래스는 DTO 옵션 비활성화 확인.
    - DTO 뱃지가 있는 클래스는 DTO 옵션 활성화 확인.
2. **로그 통합 확인:** AI 분석을 켰을 때, 정적 분석 로그가 끝난 후 AI 관련 로그("AI Analysis Start...", "Sending to LLM..." 등)가 이어서 출력되는지 확인.
3. **기능 동작:** 분석 완료 후 클래스 상세 화면의 데이터가 갱신되는지 확인.

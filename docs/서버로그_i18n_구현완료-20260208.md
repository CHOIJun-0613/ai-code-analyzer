# 서버 로그 다국어 지원 (i18n) 구현 완료 보고서

## 📋 개요

AI Code Analyzer의 서버 로그 메시지가 완전히 다국어 지원되도록 구현되었습니다.
클라이언트의 언어 설정에 따라 분석 진행 로그가 자동으로 영어 또는 한국어로 출력됩니다.

## ✅ 구현된 두 가지 언어 설정 규칙

### Rule 1: 웹 UI 언어 설정 → 클라이언트 언어에 따라 서버 로그 자동 전환
- **흐름**: 클라이언트 언어 설정(ko/en) → Accept-Language HTTP 헤더 → 서버 Accept-Language 파싱 → set_language() → logger.info(_t())
- **구현 파일**:
  - `client/src/api/client.ts`: axios request interceptor에서 Accept-Language 헤더 자동 추가
  - `server/app/api/deps.py`: get_language_from_header()로 헤더 파싱 후 ContextVar에 저장
  - `server/app/api/v1/endpoints/*.py`: 모든 분석 API에서 언어 컨텍스트 설정

### Rule 2: CLI LOG_LANGUAGE 환경변수 → CLI 실행 시 로그 언어 결정
- **흐름**: LOG_LANGUAGE=en → cli/main.py → set_language() → logger.info(_t())
- **구현 파일**:
  - `server/csa/cli/main.py`: 시작 시 LOG_LANGUAGE 환경변수 읽어 set_language() 호출
  - `server/.env.example`: LOG_LANGUAGE=ko 추가 (기본값)

## 🏗️ 구현된 인프라

### 1. 언어 컨텍스트 (Context Variable)
- **파일**: `server/csa/utils/context.py`
- **기능**: Thread-safe 언어 저장소
- **함수**:
  - `get_language()`: 현재 언어 조회 (기본값: 'ko')
  - `set_language(lang)`: 언어 설정

### 2. 번역 시스템
- **파일**: `server/csa/utils/i18n.py`
- **함수**: `_t(key, **kwargs)`
- **기능**:
  - JSON 카탈로그 기반 메시지 번역
  - 자동 폴백: 현재 언어 → 한국어 → 영어 → 메시지 키
  - Lazy Loading: 첫 사용 시만 파일 로드

### 3. 메시지 카탈로그
- **파일**: `server/csa/locales/ko.json`, `server/csa/locales/en.json`
- **총 키 수**: 228개 (한국어 + 영어 동일)
- **구조**: `{카테고리}.{서브카테고리}.{메시지_타입}` (예: `ai.rate_limit_exceeded`)

## 🔄 데이터 흐름

### 웹 UI 분석 요청 시

```
Client (Language: English)
  ↓
POST /api/v1/analysis/analyze + Accept-Language: en
  ↓
Server API Endpoint
  ├─ get_language_from_header(request) → 'en' 추출
  ├─ set_language('en') → ContextVar에 저장
  └─ start_analysis(language='en')
      ↓
      Background Thread (Language Context 상속)
      ├─ logger.info(_t("analysis.start", job_id='...'))
      │  → "Starting analysis job: ..."
      ├─ csa/services 분석 모듈들
      │  └─ logger.info(_t("neo4j.save_classes", count=150))
      │     → "Saving to DB - 150 classes..."
      └─ 진행률 로그도 모두 영어로 출력
```

### CLI 분석 실행 시

```
$ LOG_LANGUAGE=en python -m csa.cli.main analyze ...
  ↓
cli/main.py
  ├─ log_language = os.getenv("LOG_LANGUAGE", "ko") → 'en'
  ├─ set_language('en')
  └─ analyze_project()
      ↓
      logger.info(_t("analysis.start", ...))
      → "Starting analysis job: ..." (영어)
```

## 🎯 결론

서버 로그의 완전한 다국어 지원이 성공적으로 구현되었습니다.

- **Rule 1**: ✅ 웹 UI 언어 설정이 서버 로그에 자동 반영됨
- **Rule 2**: ✅ CLI LOG_LANGUAGE 환경변수로 로그 언어 제어 가능
- **확장성**: ✅ 새로운 로그는 `_t()` 함수로 간단히 추가 가능
- **신뢰성**: ✅ ContextVar 기반으로 멀티 스레드/스레드 풀 환경에서도 안전

이제 전 세계 사용자가 자신의 언어로 분석 진행 상황을 모니터링할 수 있습니다.

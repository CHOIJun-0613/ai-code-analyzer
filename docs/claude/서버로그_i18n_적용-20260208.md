# 서버로그 다국어 지원 (i18n) 구현 보고서

**작성일**: 2026-02-08
**적용 범위**: 서버 로그 메시지 전체 (클라이언트 요청 시 + CLI 실행 시)
**지원 언어**: 한국어(ko), 영어(en)

---

## 1. 개요

AI Code Analyzer 서버의 분석 로그, 에러 메시지 등을 사용자의 언어 선택에 따라 동적으로 표시하는 국제화(i18n) 시스템을 구현했습니다.

### 핵심 기능

- **웹 UI**: 클라이언트 언어 설정 → Accept-Language 헤더 → 서버 로그 자동 언어 변환
- **CLI**: 환경변수 `LOG_LANGUAGE` → 서버 로그 자동 언어 변환
- **스레드 안전성**: `ContextVar` 기반으로 백그라운드 작업에서도 언어 컨텍스트 유지
- **확장성**: JSON 카탈로그 기반으로 새 메시지 추가 용이

## 3. 두 가지 언어 설정 규칙

### 규칙 1: 웹 UI 요청 시 클라이언트 언어 우선

```
클라이언트 언어 설정 (Accept-Language 헤더)
  ↓
서버의 모든 분석 로그 & 메시지
  ↓
클라이언트 선택 언어로 동적 번역
```

**특징**:
- 클라이언트의 언어 선택이 **즉시 반영**됨
- 여러 사용자가 동시에 다른 언어로 분석 가능 (스레드-세이프)
- 환경변수 설정과 무관하게 작동

**구현 위치**:
```
1. client/src/api/client.ts (줄 14-18)
   - axios interceptor로 Accept-Language 헤더 설정

2. server/app/api/deps.py (줄 51-63)
   - Request 헤더에서 언어 추출

3. server/app/api/v1/endpoints/*.py
   - 모든 분석 엔드포인트에서 language 파라미터 획득 및 전달

4. server/app/services/analysis_wrapper.py (줄 35-41)
   - set_language(language) 호출로 백그라운드 스레드 언어 설정
```

## 7. 기술 상세

### 7.1 ContextVar를 사용한 스레드-세이프 언어 저장

```python
# server/csa/utils/context.py
from contextvars import ContextVar

language_ctx: ContextVar[Optional[str]] = ContextVar("language", default=None)

def get_language() -> str:
    """현재 스레드의 언어 반환"""
    return language_ctx.get() or "ko"

def set_language(language: str):
    """현재 스레드의 언어 설정"""
    language_ctx.set(language)
```

**장점**:
- 여러 사용자의 동시 요청이 서로 간섭하지 않음
- asyncio와 호환 가능
- 백그라운드 스레드에서도 정확한 언어 유지

### 7.2 자동 폴백 메커니즘

```python
def _t(key: str, **kwargs) -> str:
    _load_catalogs()
    lang = get_language()  # 현재 언어 (예: 'en')
    catalog = _catalogs.get(lang, {})

    # 1. 현재 언어에서 찾기
    template = catalog.get(key)

    # 2. 폴백: 한국어 시도
    if template is None and lang != "ko":
        template = _catalogs.get("ko", {}).get(key)

    # 3. 폴백: 영어 시도
    if template is None and lang != "en":
        template = _catalogs.get("en", {}).get(key)

    # 4. 폴백: 키 자체 반환
    if template is None:
        return key

    # 포맷팅
    return template.format(**kwargs) if kwargs else template
```

**효과**:
- 누락된 번역이 있어도 시스템이 정상 작동
- 새 메시지를 한국어만 추가해도 자동으로 영어로 폴백 가능

### 7.3 JSON 카탈로그 캐싱

```python
# 초기 로딩 시에만 파일 읽기
_catalogs = {}
_catalog_loaded = False

def _load_catalogs():
    global _catalogs, _catalog_loaded
    if _catalog_loaded:
        return  # 이미 로드됨

    # 첫 호출 시에만 JSON 파일 읽기
    for lang in ('ko', 'en'):
        with open(f"server/csa/locales/{lang}.json", 'r', encoding='utf-8') as f:
            _catalogs[lang] = json.load(f)

    _catalog_loaded = True
```

**성능**:
- 첫 호출 시에만 JSON 파일 읽기
- 이후는 메모리에서 빠른 조회
- 로깅 성능 영향 무시할 수준

## 11. 문제 해결

### Q: 특정 메시지가 한국어로 나옵니다 (영어 설정 중)

**원인**: 해당 메시지가 `en.json`에 없음

**해결**:
1. `server/csa/locales/en.json`에 해당 키의 영어 번역 추가
2. 또는 `_t()` 호출을 추가 전 `_load_catalogs()` 재호출

```python
# ko.json에 추가
"mymodule.message": "한국어 메시지"

# en.json에도 추가
"mymodule.message": "English message"
```

### Q: CLI에서 언어 설정이 적용되지 않습니다

**확인 항목**:
1. `server/.env`에 `LOG_LANGUAGE=en` 설정 확인
2. CLI 진입점에서 `set_language(log_language)` 호출 확인
3. 로그 메시지가 `_t()` 함수를 사용하는지 확인

```bash
# 환경변수 확인
cat server/.env | grep LOG_LANGUAGE

# 출력 예상: LOG_LANGUAGE=en
```

### Q: 언어 컨텍스트가 다음 요청으로 유지됩니다

**정상 동작입니다**:
- 각 API 요청 시마다 `get_language_from_header()` 호출로 새 언어 설정
- 다른 사용자의 요청은 독립적으로 처리됨 (ContextVar 기반)

# Server/CSA 분석 및 개선 보고서

이 보고서는 `/server/csa` 코드베이스 내에서 유지보수성, 코드 품질, 아키텍처 일관성 측면에서 개선이 필요한 주요 영역을 정리한 것입니다.

## 1. 중요: 코드 복잡도 및 함수 크기
일부 파일과 함수가 권장 크기 제한(파일 < 1000줄, 함수 < 100줄)을 위반하여 심각한 유지보수 위험을 초래하고 있습니다.

### `csa/services/graph_db/project_nodes.py` (1502줄)
이 파일은 매우 비대하며 Graph DB 트랜잭션을 처리하는 거대한 모놀리식 함수들을 포함하고 있습니다.
- **문제점**: 
  - `_create_class_node_tx`: 약 600줄.
  - `_create_classes_batch_tx`: 약 650줄.
  - 데이터 추출/변환, JSON 직렬화, Cypher 쿼리 생성이 한 곳에 뒤섞여 있습니다.
- **개선 방안**:
  - **헬퍼 함수로 리팩토링**: 하위 레코드(Method, Field, Annotation) 생성 로직을 별도 헬퍼 함수로 추출합니다.
    - 예: `_build_method_records(class_node) -> list[dict]`
    - 예: `_build_field_records(class_node) -> list[dict]`
  - 이를 통해 "데이터 준비" 단계와 "DB 실행" 단계를 명확히 분리합니다.

### `csa/services/ai_enrichment_service.py`
- **문제점**: 
  - `_enrich_methods_async`: 약 150줄.
  - 메인 로직 내에 중첩된 루프와 조건문으로 인해 순환 복잡도가 높습니다.

## 2. 코드 중복
"단일 모드"와 "배치 모드" 간, 그리고 "동기"와 "비동기" 서비스 간에 상당한 로직 중복이 존재합니다.

- **Graph DB 로직**: `_create_class_node_tx`와 `_create_classes_batch_tx`는 `Class` 객체를 Neo4j 파라미터로 변환하는 데 있어 거의 동일한 로직을 공유합니다. 데이터 모델 변경 시 두 함수를 모두 수정해야 하므로 오류 발생 가능성이 높습니다.
  - **개선 방안**: `Class` 객체를 단일 및 배치 트랜잭션 모두에서 사용할 수 있는 파라미터/레코드 딕셔너리로 변환하는 통합 `ClassToNeo4jConverter` 유틸리티를 생성합니다.

- **동기/비동기 래퍼**: `AIEnrichmentService`는 유사한 로직 흐름으로 동기(`enrich_project`) 및 비동기(`enrich_project_async`) 버전을 모두 구현하고 있습니다.
  - **개선 방안**: 핵심 로직은 비동기로 구현해야 합니다. 동기 메서드는 단순히 `asyncio.run()`을 사용하는 경량 래퍼로 만들거나, 가능한 경우 순수 비동기 아키텍처를 위해 제거하는 것이 좋습니다.

## 3. 데이터 모델 구조
### `csa/models/graph_entities.py`
- **문제점**: 이 단일 파일에 `Project`, `Class`, `Method`, `SqlStatement`, `Bean`, `Endpoint`, `ConfigFile` 등 모든 모델이 정의되어 있습니다.
- **개선 방안**: 도메인별 모듈로 분리합니다:
  - `csa/models/java.py` (Class, Method, Field, Annotation)
  - `csa/models/db.py` (Database, Table, Column, SqlStatement)
  - `csa/models/config.py` (ConfigFile, ServerConfig, LoggingConfig)
  - `csa/models/project.py` (Project, Package)

## 4. 아키텍처 명확성: 파서 vs 서비스
- **문제점**: 명칭 충돌 및 책임 분산.
  - `csa/parsers/java`: 로직 헬퍼(`logical_name.py`)를 포함.
  - `csa/services/java_analysis`: 핵심 파싱 로직(`project.py`) 포함.
  - `csa/services/java_parser.py`: `java_analysis` 함수를 재수출하는 파사드.
- **개선 방안**:
  - 파싱 로직을 통합합니다. `csa/parsers`가 저수준 파싱(AST 조작)을 위한 목적이라면, `javalang` 관련 코드를 그쪽으로 이동시킵니다.
  - `csa/services/java_parser.py`가 단순히 레거시 파사드라면 이름을 변경하거나, 불필요한 간접 참조를 줄이기 위해 import를 인라인화합니다.

## 5. 권장 조치 사항 요약
1.  **`project_nodes.py` 리팩토링**: 거대한 트랜잭션 함수를 즉시 분할합니다. 유지보수성을 위해 가장 시급한 작업입니다.
2.  **`graph_entities.py` 분리**: Pydantic 모델을 모듈화합니다.
3.  **DB 변환 로직 통합**: 단일/배치 DB 삽입 로직 간의 중복을 제거합니다.

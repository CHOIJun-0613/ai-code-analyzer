## 2. 개선 가능 영역 분석

### 2.1 프론트엔드 개선

#### 2.1.1 Operation 노드 커스텀 컴포넌트화

**현재 상태**: Operation 노드는 ReactFlow의 기본 `default` 타입에 인라인 스타일 적용

```tsx
// 현재 코드 (SqlFlowViewer.tsx:123-137)
case 'operation':
    reactFlowType = 'default';
    style = {
        background: '#fff7ed',
        border: '2px solid #f97316',
        // ... 인라인 스타일
    };
```

**개선 방안**: `OperationNode.tsx` 커스텀 컴포넌트 생성
- operationType별 아이콘 추가 (Filter, Sort, Group 등)
- condition 표시 개선 (툴팁 또는 확장 가능한 섹션)
- 다크 모드 지원 (현재 미지원)

**예상 효과**:
- 코드 모듈화 및 유지보수성 향상
- 시각적 가독성 개선
- 다크 모드 일관성 확보

---

#### 2.1.2 레이아웃 방향 전환 기능

**현재 상태**: 좌→우(LR) 방향 고정

**개선 방안**:
- TB(상→하) 방향 전환 버튼 추가
- 복잡한 SQL의 경우 TB가 더 가독성 좋을 수 있음

**구현 위치**: `SqlFlowViewer.tsx` - 레이아웃 방향 state 추가

---

#### 2.1.3 노드 그룹핑 (Subgraph) 기능

**현재 상태**: 모든 노드가 동일 레벨에 표시

**개선 방안**:
- 서브쿼리를 시각적 그룹(박스)으로 묶기
- ReactFlow의 `groupNode` 또는 Background Panel 활용
- JOIN 연산 관련 노드 그룹핑

**예상 효과**: 복잡한 SQL의 계층 구조 이해도 향상

---

#### 2.1.4 노드 상세 정보 패널

**현재 상태**: 노드에 기본 정보만 표시

**개선 방안**:
- 노드 클릭 시 사이드 패널 또는 모달로 상세 정보 표시
  - 테이블: 전체 컬럼 목록, 인덱스 정보, 관련 SQL
  - Operation: 전체 조건문, 예상 성능 영향
- 노드 간 연결 관계 하이라이트

---

#### 2.1.5 확대/축소 및 네비게이션 개선

**현재 상태**: ReactFlow 기본 Controls, MiniMap 사용

**개선 방안**:
- 확대/축소 버튼 커스터마이징
- 특정 노드로 포커스 이동 기능 (노드 검색)
- MiniMap 스타일 커스터마이징 (노드 타입별 색상)

---

#### 2.1.6 애니메이션 효과

**현재 상태**: 정적 시각화

**개선 방안**:
- 데이터 흐름 방향 애니메이션 (엣지 라인 애니메이션)
- 노드 호버 시 연결된 경로 하이라이트
- 초기 로딩 시 노드 순차 등장 애니메이션

**참고**: ReactFlow의 `animated` 속성 활용 가능

### 2.2 백엔드 개선

#### 2.2.1 SQL Flow JSON 사전 생성 및 캐싱

**현재 상태**: API 호출 시마다 `normalize_and_extract()` 실행

```python
# 현재 코드 (sqls.py:153-158)
ai_description = sql_data.get("ai_description")
if ai_description:
    flow_json = normalize_and_extract(ai_description)
    if flow_json:
        sql_data["flow_json"] = flow_json
```

**개선 방안**:
- AI Enrichment 완료 시 `flow_json`을 Neo4j에 별도 필드로 저장
- 조회 시 정규화 로직 스킵하여 성능 향상

**구현 위치**: `ai_enrichment_service.py` - AI 결과 저장 시 함께 정규화

---

#### 2.2.2 정규화 로직 강화

**현재 상태**: 기본적인 노드/엣지 정규화만 수행

**개선 방안**:

1. **노드 위치 힌트 추가**
   - AI가 생성한 JSON에서 노드 순서 정보 활용
   - 정규화 시 `rank` 또는 `order` 필드 추가
   ```python
   normalized["rank"] = index  # 처리 순서
   ```

2. **순환 참조 감지**
   - 엣지에서 사이클 감지 로직 추가
   - 사이클 발견 시 경고 또는 자동 보정

3. **컬럼 매핑 정보 보존**
   - 현재 컬럼 레벨 연결은 노드 레벨로 변환됨
   - 컬럼 매핑 정보를 별도 필드로 보존 (상세 뷰에서 활용)
   ```python
   normalized["column_mappings"] = [
       {"source": "table.col1", "target": "result.col1"}
   ]
   ```

---

#### 2.2.3 JOIN 노드 처리 개선

**현재 상태**: JOIN은 단일 operation 노드로 표현

```python
# 현재 코드 (sql_flow_normalizer.py:211-213)
elif edge_type in ("join", "inner_join", "left_join", "right_join"):
    op_type = "JOIN"
    op_label = edge_type.upper().replace("_", " ")
```

**개선 방안**:
- 다중 JOIN 시 각 JOIN을 별도 노드로 분리
- JOIN 조건을 상세히 표시
- JOIN 타입별 시각적 구분 (INNER, LEFT, RIGHT, FULL)

---

#### 2.2.4 AI 프롬프트 개선

**현재 상태**: `default_prompts.py`의 `sql_doc` 프롬프트 사용

**개선 방안**:

1. **INSERT/DELETE 문 예시 추가**
   - 현재 SELECT, UPDATE 예시만 있음
   - INSERT (VALUES, SELECT INTO), DELETE 예시 추가

2. **복합 SQL 처리 가이드**
   - UNION, INTERSECT, EXCEPT 처리 방법
   - CTE (Common Table Expression) 처리 방법

3. **오류 케이스 가이드**
   - AI가 생성하는 일반적인 오류 패턴 명시
   - 금지 패턴 강화 (컬럼 레벨 엣지 등)

---

#### 2.2.5 SQL 파서 활용 강화

**현재 상태**: `parser.py`가 있으나 Flow 생성에 직접 활용되지 않음

**개선 방안**:
- SQL 파서 결과를 AI 프롬프트의 힌트로 제공
- 파싱 실패 시 기본 Flow 자동 생성 (테이블만 표시)
- 복잡도 점수 기반 레이아웃 조정 힌트

```python
# 예시: 파서 결과를 AI 프롬프트에 추가
sql_analysis = parser.parse_sql_statement(sql_content, sql_type)
prompt += f"\n[참고: 테이블={sql_analysis.tables}, JOIN={sql_analysis.joins}]"
```

## 4. 기술적 고려사항

### 4.1 ReactFlow 업그레이드

현재 버전: `reactflow@11.11.4`

- ReactFlow v12로 업그레이드 시 API 변경 사항 확인 필요
- 새로운 기능 (Sub-flows, Better Touch Support) 활용 가능

### 4.2 상태 관리

현재: 컴포넌트 로컬 상태 (`useState`, `useNodesState`)

복잡한 기능 추가 시:
- Zustand 스토어로 Flow 상태 관리 분리 고려
- 노드 선택, 편집 모드 등 전역 상태 필요 시

### 4.3 테스트 고려사항

- SQL Flow 정규화 로직 단위 테스트 추가
- 다양한 SQL 패턴에 대한 시각화 스냅샷 테스트
- 대용량 데이터 성능 테스트

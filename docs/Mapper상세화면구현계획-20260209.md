# SQL Mapper 상세 화면 구현 계획

## Context
현재 MapperList 페이지는 목록만 표시하고 상세 화면이 없음. Mapper를 클릭해도 아무 동작이 없음.
이 작업은 (1) MyBatisMapper 노드에 source 속성을 추가하여 분석 시 XML 원본을 저장하고, (2) Mapper 상세 화면을 구현하여 개요/등록SQL/소스를 볼 수 있게 함.

---

## 과제1: MyBatisMapper 노드에 source 속성 추가

### 1-1. Pydantic 모델에 source 필드 추가
- **파일**: `server/csa/models/entities/mybatis.py`
- `MyBatisMapper` 클래스에 `source: str = ""` 필드 추가

### 1-2. XML 파서에서 source 저장
- **파일**: `server/csa/services/java_analysis/mybatis.py`
- `parse_mybatis_xml_file()` 함수 (512행): 이미 `xml_content = f.read()`로 파일 내용을 읽고 있음
- MyBatisMapper 생성 시 `source=xml_content` 추가 (649행)

### 1-3. Java Interface 파서에서도 source 저장
- **파일**: `server/csa/services/java_analysis/mybatis.py`
- `extract_mybatis_mappers_from_classes()` 함수 (393행): Java Class 객체의 source를 mapper.source에 저장

### 1-4. Neo4j 저장 쿼리에 source 추가
- **파일**: `server/csa/services/graph_db/persistence_nodes.py`
- `_create_mybatis_mapper_node_tx()` (87행): MERGE 쿼리의 SET절에 `m.source = $source` 추가
- tx.run 파라미터에 `source=mapper.source or ""` 추가

## 과제2: SQL Mapper 상세 화면 구성

### 2-1. 백엔드 API - Mapper 상세 엔드포인트 추가
- **파일**: `server/app/api/v1/endpoints/mappers.py`
- 새 엔드포인트: `GET /mappers/projects/{project_name}/mappers/{mapper_name}`
- SqlDetails API (sqls.py:118행) 패턴을 참조
- 반환 데이터:
  - MyBatisMapper 노드 전체 속성 (name, logical_name, type, file_extension, namespace, file_path, package_name, ai_description, source, updated_at)
  - sql_statements (JSON 파싱하여 리스트로 반환)
  - sql_count

### 2-2. 프론트엔드 - MapperDetails 페이지 생성
- **새 파일**: `client/src/pages/MapperDetails.tsx`
- SqlDetails.tsx (711행) 패턴을 참조하여 구현

#### Header 구성:
- FileCode 아이콘 (indigo 배지)
- `package_name` 표시
- `name + "." + file_extension` 표시
- type 배지 (xml/interface)
- logical_name 표시
- updated_at 표시

#### 탭 구성 (3개):
1. **'개요' 탭 (overview)**:
   - 파일 경로: `file_path` 값 표시
   - Description: `ai_description` 값을 Markdown으로 렌더링 (react-markdown + remarkGfm)

2. **'등록 SQL' 탭 (sqlStatements)**:
   - sql_statements에서 id, logical_name, sql_type 컬럼으로 테이블 구성
   - id 클릭 시 `/projects/{projectName}/sqls/{sqlId}?mapper={mapperName}` 으로 이동

3. **'Mapper 소스' 탭 (source)**:
   - SourceCodeViewer 컴포넌트 사용 (SqlDetails의 SQL Source 탭과 동일)
   - language="xml" 로 설정

### 2-3. 라우팅 등록
- **파일**: `client/src/App.tsx`
- 새 라우트: `projects/:projectName/mappers/:mapperName`
- lazy import 추가

### 2-4. MapperList에서 상세 화면 이동 추가
- **파일**: `client/src/pages/MapperList.tsx`
- VirtualizedTable에 `onRowClick` 핸들러 추가
- 클릭 시 `/projects/{projectName}/mappers/{mapperName}?package={packageName}` 으로 navigate

### 2-5. i18n 번역 키 추가
- **파일**: `client/src/locales/ko/translation.json`, `client/src/locales/en/translation.json`
- `mapperDetails` 섹션 추가:
  - 탭: overview, sqlStatements, mapperSource
  - 헤더: filePath, description, noDescription
  - SQL 테이블: sqlId, logicalName, sqlType, noSqlStatements
  - 공통: loading, error, notFound

### 2-6. 다크/라이트 모드
- 기존 패턴 (Tailwind `dark:` prefix) 그대로 적용
- SourceCodeViewer 자동 지원 (MutationObserver로 dark class 감지)

## 검증 방법

1. **백엔드 검증**: 서버 실행 후 `GET /api/v1/mappers/projects/{project}/mappers/{mapper}` API 호출하여 source 포함 여부 확인
2. **프론트엔드 검증**: MapperList에서 Mapper 행 클릭 → MapperDetails 페이지 이동 → 3개 탭 전환 확인
3. **다크모드 검증**: 설정에서 테마 전환 후 MapperDetails 화면 표시 확인
4. **i18n 검증**: 언어 전환(한국어/English)하여 번역 표시 확인
5. **SQL 이동 검증**: 등록 SQL 탭에서 SQL id 클릭 시 SqlDetails로 정상 이동 확인

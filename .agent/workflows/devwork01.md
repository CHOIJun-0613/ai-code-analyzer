# Workflow: 체계적 코드 수정 및 문서화 프로세스 (v2.0)

이 워크플로우는 기존 코드를 분석하여 계획을 수립하고, 구현 및 품질 검증을 거쳐 결과 보고서를 작성하는 **End-to-End 개발 프로세스**입니다.

## 0. 사전 준비 (Configuration)
작업 시작 전, 아래 변수를 확인하고 환경을 설정합니다.
- **수정제목 (Title)**: (예: 사용자로그인기능개선)
- **일련번호 (Seq)**: (예: 001)
- **기본 경로 규칙**: 모든 문서는 프로젝트 루트(Project Root) 기준 **상대 경로(`./`)**를 사용합니다.

---

## Step 1: 구조 분석 (Deep Analysis)
1. 요청된 작업과 관련된 프로젝트 내의 소스 코드를 심층 분석합니다.
2. 코드의 의존성(Dependency), 호출 관계(Call Hierarchy), 데이터 흐름(Data Flow)을 파악합니다.
3. **Check**: 수정 시 사이드 이펙트가 발생할 수 있는 지점을 미리 식별합니다.

## Step 2: 계획 수립 및 문서화 (Planning)
1. 분석 결과를 바탕으로 구현 계획 문서를 작성합니다.
2. **Directory Check**: `./docs/antigravity/` 폴더가 없다면 생성합니다.
3. **문서 작성**:
   - **경로 및 파일명**: `./docs/antigravity/{{수정제목}}-{{일련번호}}-수정계획-YYYYMMDD.md`
   - **필수 내용**: 현상 분석, 수정 목표, 상세 구현 시나리오, 영향도 분석

## Step 3: 구현 (Implementation)
1. `Step 2`의 [수정계획 문서]를 기준으로 코딩을 진행합니다.
2. 기존 로직의 안정성을 유지하면서 요구사항을 정확히 반영합니다.

## Step 4: 즉시 검증 (Verification)
1. 구현된 코드가 계획 문서의 항목을 모두 충족하는지 대조합니다.
2. 누락된 요구사항이 있다면 즉시 추가 구현합니다.

## Step 5: 코드 품질 검토 (Code Quality Review)
1. 수정된 코드에 대해 아래 기준으로 자체 코드 리뷰를 수행합니다.
   - **가독성**: 명명 규칙(Naming Convention) 준수 및 주석 적절성
   - **효율성**: 불필요한 중복 코드, 비효율적 루프 제거
   - **안전성**: 예외 처리(Exception Handling) 및 Null 처리 적절성

## Step 6: 리팩토링 (Refactoring)
> **Condition**: `Step 5`에서 개선점이 발견된 경우 실행
1. 리뷰 피드백을 반영하여 코드를 개선합니다.
2. 리팩토링 후 기능 동작에 변화가 없는지 확인합니다.

## Step 7: 테스트 (Testing)
> **Condition**: 로직 검증을 위해 테스트 코드가 필수적인 경우 실행
1. **Directory Check**: `./tests/` 폴더가 존재하는지 확인합니다.
2. 테스트 코드를 작성하고 실행하여 기능의 정상 동작을 보증합니다.
   - 테스트 파일 경로: `./tests/` 하위

## Step 8: 완료 검토 및 클린업 (Final Review & Cleanup)
1. **재작업 판단**: 구현 내용이 불충분하다면 `Step 3`로 돌아갑니다.
2. **클린업**: 디버깅을 위해 임시로 생성한 로그, 주석, 임시 파일들을 삭제합니다.

## Step 9: 결과 문서화 (Documentation)
1. 모든 작업 결과를 종합하여 최종 문서를 작성합니다.
2. **문서 작성**:
   - **경로 및 파일명**: `./docs/antigravity/{{수정제목}}-{{일련번호}}-작업결과-YYYYMMDD.md`
   - **필수 내용**:
     - 작업 요약 (Summary)
     - 주요 변경 사항 (Changes) - 파일명과 변경 핵심 내용
     - 테스트 결과 (Test Report)
     - **Git Commit Message Recommendation**: (제목과 본문 형식 준수)
